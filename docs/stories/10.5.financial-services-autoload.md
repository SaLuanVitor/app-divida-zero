# Story 10.5 — Corrigir autoload dos serviços financeiros (namespace Zeitwerk)

## Status
Draft

## Story
**As a** desenvolvedor do backend,
**I want** que as classes de `app/services/financial/` resolvam por autoload em dev/teste,
**so that** o gate do Open Finance (`FeatureFlags`) e a suíte de testes funcionem sem depender do eager_load de produção.

## Contexto e Decisão
- Os arquivos em `app/services/financial/` declaram classes **top-level** (`FeatureFlags`, `LimitsService`, `TransactionNormalizer`) e o módulo `FinancialProviders`, mas o path `app/services/financial/` faz o Zeitwerk esperar `Financial::*`.
- Consequência: em **dev/teste** (eager_load off) dá `NameError: uninitialized constant` ao referenciar essas classes. Em **produção** (eager_load on) funciona por acaso, porque tudo é carregado no boot.
- Descoberto no gate do Pluggy (ADR-0003): `ConnectionsController#check_open_finance_enabled` usa `FeatureFlags.enabled?(:open_finance)`, que **quebra em dev/teste** — ou seja, o gate só vale em produção hoje. O `FinancialSyncJob` contornou usando o model `FeatureFlag` (autoload ok).
- Decisão: normalizar o namespace para `Financial::*` (padrão Rails/Zeitwerk) e atualizar as referências. Alternativa rejeitada por ora: mover arquivos para `app/services/` (top-level), que deixaria a árvore inconsistente.

## Acceptance Criteria
1. [ ] `FeatureFlags`, `LimitsService`, `TransactionNormalizer` e `FinancialProviders::*` resolvem via autoload (Zeitwerk) em dev/teste, sem `require` manual.
2. [ ] `bundle exec rails zeitwerk:check` sai limpo (sem "expected … to define …").
3. [ ] Referências atualizadas em `connections_controller`, `financial_controller`, `financial_sync_job` e demais consumidores.
4. [ ] Testes que falhavam com `NameError` (`feature_flags_test`, `financial_sync_job_test`, etc.) passam a carregar as constantes.

## Tarefas / Subtasks
- [ ] Mapear classes de `app/services/financial/` e todos os consumidores (AC #1)
- [ ] Aplicar namespace `Financial::` nos serviços e `Financial::Providers` nos providers (AC #1)
- [ ] Atualizar referências nos controllers/jobs (AC #3)
- [ ] Rodar `zeitwerk:check` (AC #2)
- [ ] Rodar a suíte afetada 1 arquivo por vez (AC #4)

## Dev Notes
### Onde está o problema
```
app/services/financial/feature_flags.rb            # class FeatureFlags (Zeitwerk espera Financial::FeatureFlags)
app/services/financial/limits_service.rb           # class LimitsService
app/services/financial/transaction_normalizer.rb   # class TransactionNormalizer
app/services/financial/providers/factory.rb        # module FinancialProviders (espera Financial::Providers)
app/services/financial/providers/{base,manual_adapter,pluggy_adapter}.rb
```
### Consumidores (não exaustivo)
- `ConnectionsController`: `FeatureFlags.enabled?`, `LimitsService.*`, `FinancialProviders::Factory`
- `FinancialController` (admin): `FinancialProviders::Factory`
- `FinancialSyncJob`: `FinancialProviders::Factory`, `TransactionNormalizer` (usa o model `FeatureFlag`, ok)
- Testes: `feature_flags_test`, `financial_sync_job_test`, `limits_service_test`, `financial_provider_factory_test`, etc.

### Observações
- `FinancialSyncJob` já usa o **model** `FeatureFlag` (autoload ok); o que quebra é o **serviço** `FeatureFlags`.
- Existem outros defeitos pré-existentes nos testes do Pluggy (10.1–10.3) além do autoload — ex.: `Bank::DeduplicationService.duplicate?` inexistente, validação `Provider can't be blank`, mocks de Minitest. Escopo separado desta story.

## Dependencies
- `config/application.rb` (autoload padrão Rails 8.1 + Zeitwerk)

## Complexity
M (refatoração de namespace tocando vários arquivos + testes)

## Risks
- **Médio**: renomear namespaces pode quebrar referências esquecidas; mitigar com `zeitwerk:check` + suíte.
- **Baixo em produção**: o eager_load mascara o bug hoje, então a mudança é transparente em prod.
