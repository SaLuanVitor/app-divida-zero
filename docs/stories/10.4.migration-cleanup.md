# Story 10.4: Migration, Cleanup & OFX/CSV Fallback

## Status
InReview

## Story
**As a** desenvolvedor do App Dívida Zero,
**I want** migrar o upload OFX/CSV legacy para usar o novo adapter, manter fallback e limpar código obsoleto,
**so that** o sistema tenha uma única pipeline de importação bancária com suporte a múltiplas fontes.

## Acceptance Criteria
1. `Bank::StatementsController` refatorado para usar `FinancialProviderFactory` + `TransactionNormalizer`
2. Upload OFX/CSV cria `FinancialConnection` com `provider: 'manual'` + `FinancialSync` → mesma pipeline
3. `Bank::OfxParser` e `Bank::CsvParser` adaptados para retornar formato compatível com `TransactionNormalizer`
4. `Bank::DeduplicationService` e `Bank::AiCategorizationService` reaproveitados (já funcionam)
5. Feature flag `manual_import` controla disponibilidade do upload OFX/CSV
6. Remoção segura de código obsoleto:
   - `StatementParseJob` → substituído por `FinancialSyncJob`
   - `Bank::StatementParsingService` legacy → removido
   - `Bank::StatementsController` → **mantido como deprecated** (retorna 410 + redirect para nova API) para não quebrar mobile app existente
   - `Bank::TransactionsController` → **mantido como deprecated** (retorna 410 + redirect)
7. Migração de dados: `ImportedTransaction` existentes → `FinancialRecord` (já feito via accept) — sem ação necessária
8. Documentação atualizada: `README.md` com nova arquitetura, `docs/guides/bank-integration.md`
9. Testes de regressão: upload OFX → sync → accept → financial_record criado
10. Testes de regressão: upload CSV → sync → accept → financial_record criado
11. Benchmark: tempo de importação 1000 transações OFX < 5s, CSV < 3s (ambiente: CI com fixtures reais)
