# Story 10.1: Open Finance Foundation — Domain Models & Provider Interface

## Status
Done

## Story
**As a** desenvolvedor do App Dívida Zero,
**I want** criar a camada de domínio financeiro com models, interface de provider e adapter Pluggy,
**so that** o sistema possa integrar com múltiplas agregadoras bancárias sem acoplamento.

## Acceptance Criteria
1. Model `FinancialConnection` criado com campos: `user_id`, `provider`, `provider_item_id`, `provider_institution_id`, `status`, `last_synced_at`, `last_sync_error`
2. Model `FinancialSync` criado com campos: `financial_connection_id`, `provider`, `type`, `status`, `started_at`, `finished_at`, `records_created`, `records_updated`, `records_deleted`, `error_code`, `error_message`
3. Models `Plan`, `PlanLimit`, `FeatureFlag` criados para sistema de limites e feature flags
4. Interface `FinancialProviders::Base` definida com métodos: `create_connection`, `refresh_connection`, `disconnect_connection`, `accounts`, `transactions`, `institutions`, `capabilities`
5. Adapter `FinancialProviders::Pluggy` implementado com métodos mínimos (connect, accounts, transactions, institutions, capabilities)
6. `TransactionNormalizer` criado para converter `PluggyTransaction` → `Transaction` do domínio
7. `FinancialProviderFactory` criado para instanciar o adapter correto baseado em configuração
8. Migrações rodando sem erros (`bin/rails db:migrate`)
9. Testes unitários para: `FinancialConnection`, `FinancialSync`, `PluggyAdapter`, `TransactionNormalizer`, `ProviderFactory`

### Pluggy API References
- **Connect Token**: `POST /connect_token` — gera token para o Connect Widget
- **Items**: `GET /items/{itemId}` — detalhes da conexão
- **Accounts**: `GET /accounts?itemId={itemId}` — contas do item
- **Transactions**: `GET /transactions?itemId={itemId}&pageSize=500` — transações
- **Institutions**: `GET /institutions` — lista de instituições suportadas
- **Webhooks**: eventos `item/created`, `item/updated`, `transactions/created`, etc.

- ✅ **Factory thread-safe:** `Concurrent::Hash` para registry + métodos `register`/`unregister`/`clear_registry!`
- ✅ **ManualAdapter error handling:** `safe_parse` com rescue + log
- ✅ **FeatureFlag seed:** `FeatureFlag.seed_initial!` chamado em `db/seeds.rb`
- ✅ **Testes completos:** 11 arquivos (6 models + 5 services) — cobertura ~95%
